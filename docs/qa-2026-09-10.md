## Corrections included

- Duplicate-expert scoring uses the current completeness calculation instead of a deleted helper.
- Public availability excludes past/occupied/overlapping choices while preserving the owner's editable schedule. Slot-list replacements and profile writes compare the reservation snapshot rather than overwriting a concurrent reservation. No extra per-card database scan or new infrastructure.
- Chat refresh uses the existing messages endpoint every 15 seconds only for an open, visible confirmed conversation; errors back off up to 60 seconds. Archived reads do not continually poll. Responses are discarded after a conversation/session switch, and messages merge by ID to avoid erasing a just-sent message.
- Archived history is readable by its participants only; sending still requires a confirmed booking. The read response includes booking status so a cancelled session loses its send UI on refresh. This is a compatible addition to the existing API; no new gateway route is required.
- Conversation loading errors are visible and retryable, instead of silently displaying an empty inbox. The dashboard now waits for profile initialization before fetching role-dependent booking data.
- Missing application profiles initialize on first use. Concurrent first bootstrap cannot overwrite the profile created by another request. Cognito group-role reconciliation updates only the role, preserving saved personal fields and points. An expert without a draft receives a private editable draft, not a paid membership or visibility bypass.
