# GrowPoint QA — 2026-09-06

Scope: the deployed website, owner-supplied client and consultant accounts, read-only AWS verification, and local removal of the retired static examples. Only the supplied accounts and synthetic QA files were modified. No credentials, tokens, private storage paths, or account identifiers are included here.

## Findings and release blockers

| Priority | Finding | Evidence / next action |
| --- | --- | --- |
| High | Existing application roles can remain stale after a Cognito group change. | Before testing, both supplied accounts already had DynamoDB user records. The expert belonged to Cognito's `consultants` group but its DynamoDB role was `client`; ordinary login never called bootstrap. Explicitly invoking the existing bootstrap endpoint changed it to consultant and created its draft. Prepare a session/onboarding synchronization fix; do not rewrite profile data on every background request. |
| Medium | An expert cannot reach 100% through the available form. | All visible expert fields and availability saved, but completion remained 82%. Both frontend and monitoring count private occupation, age, and bio fields while the private-profile form is hidden from experts. Align the completion criteria with editable fields or expose the missing fields. Do not fill invisible fields directly in DynamoDB to mask this. |
| Blocking test prerequisite | The demonstration expert has no active membership. | Saved expert record has `comped=false`, no granted/purchased package, and `isPublic=false`; public profile lookup returns 404. This is correct access gating, not failed persistence. Owner approval for a complimentary membership is pending; no paid state or entitlement was fabricated. |
| Release prerequisite | SES production access remains disabled. | Read-only SES account check reported production access false and sending enabled. General transactional-email delivery cannot be certified in this state. |
| Low | Direct `/legal` navigation returns HTTP 404. | Browser eventually redirects to `/terms` through the SPA, but the initial document response is 404. The FAQ links to this alias. Link directly to `/terms` and/or generate an alias document. |

## Verified on the deployed site

- Both supplied accounts sign in with their existing credentials; no password reset or authentication bypass was used. Both were signed out afterward and protected dashboard navigation returned to login.
- Client profile: all four form steps, portrait upload, save, reload, 100% completion, and a single 20-point completion award.
- Expert profile: public name and slug, labelled fictional biography, portrait upload, specializations, topics, audience, experience, languages, session format, and three future availability slots saved successfully.
- Expert type switch to mentor survives reload; restored to consultant afterward.
- Direct DynamoDB reads confirm both user records, correct roles after the explicit expert bootstrap, saved names/avatar keys, client points, and the client's QA document metadata.
- Synthetic document upload, reload and owner download work. Downloaded bytes match the uploaded file. A second temporary file was uploaded and removed through the UI; the main QA document is retained. The consultant cannot obtain that unshared document's download URL (403).
- Client data export returns its own saved QA data (200). Client access to admin statistics is denied (403); anonymous protected API requests are denied (401).
- DKS preview has no card inputs, the payment action is disabled, Escape closes it, focus returns to the trigger, and opening/closing it sends no API mutation.
- Client and expert dashboard layouts have no horizontal overflow at 390px and 1440px; uploaded portraits load. Screenshots are local, ignored QA artifacts, not public documentation.
- Earlier in this QA pass: 18 public/protected/unknown routes checked at both widths without application JavaScript exceptions; expected not-found behaviour, authentication redirects, catalogue filters, static example images/pages, and registration validation were exercised. The static examples were subsequently retired at the owner's request.
- Google, Apple and LinkedIn initiate their provider sign-in screens. Completing those provider logins was not attempted without provider credentials.
