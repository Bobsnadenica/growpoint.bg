## Reproducible open issues

1. **Duplicate-expert regression:** run `npm test`; canonical selection still references the removed auto-approval helper. Fix and add coverage without reintroducing obsolete approval or membership behavior.
2. **Direct public-profile 404:** open the current expert's detail page in a new tab or refresh it; the document response is 404 despite a successful profile API response. Review the generated GitHub Pages route output and publish through the owner's normal workflow, then retest the HTTP status.
3. **Occupied availability remains selectable:** the public calendar and reschedule choices advertise the slot belonging to the pre-existing pending booking. The attempted booking is rejected with an overlap error, correctly preventing that conflict. Filter occupied choices and retain the backend conflict guard; do not remove or alter the existing booking to hide the symptom.
4. **Stale conversation:** keep the expert's thread open, send from the client, then close/reopen the thread. The reply appears only after full page reload in this run. Add a bounded refresh strategy or explicit refresh affordance and test unread state; no always-on infrastructure is needed for this fix.

## Test data and remaining gates

The labelled QA booking and two messages remain as a cancelled, unpaid audit record. The synthetic client document remains private, with expert sharing revoked. Do not bypass payment or membership gates to obtain a passing result.

No production fixes were deployed. Re-run the automated suite, strict public-profile smoke and affected authenticated scenarios after the owner deploys corrections. Passing this scoped lifecycle does not certify the whole website.
